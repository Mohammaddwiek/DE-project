● Step 2: Extraction

  What extraction means

  Extraction is the first stage of a data pipeline. We pull the data out of its
  source, here a web API, and save it exactly as we got it, with no changes.
  That saved copy is our raw data and goes in data/raw/. Every later step
  (flattening, profiling, cleaning) reads from that file, not from the API.

  Three ideas to understand here:

  - API: a web address that returns data instead of a web page. You send a
    request to a URL and get JSON back.
  - JSON: nested text data. One country is an object, and inside it there are
    more objects (currencies), lists (borders) and lists of objects (languages).
    That nesting is why step 3, flattening, exists.
  - Raw stays raw: we never edit the raw file. If cleaning goes wrong, we rerun
    it from the raw file. We don't call the API again, and the data can't drift
    on us.

  An important finding: the API has changed

  I checked the official site before explaining, and it affects our plan:

  - The old version (v3.1, restcountries.com/v3.1/all), which most tutorials and
    probably your syllabus refer to, is now marked "Deprecated". The site says
    support for versions 1 to 4 has ended.
  - The new version is v5, at api.restcountries.com/countries/v5. Compared with
    v3.1:
    - It needs a free API key, a password-like token you sign up for.
    - It is paginated: at most 100 countries per request on the free plan. For
      about 250 countries we'd make about 3 requests and combine them.
    - The field names are different. For example, names.common replaces
      name.common, and codes.alpha_3 replaces cca3.

● What flattening means

  Our raw file is nested: one country contains boxes inside boxes. pandas,
  charts and statistics need a flat table: one row per country, one column per
  piece of information, and one simple value per cell (a number, a word,
  true/false).

  Flattening means turning the nested JSON into that table. The result is still
  not cleaned: we don't fix or remove anything yet. We only change the shape.

  The 4 kinds of fields in our data (Jordan as the example)

  1. Simple values: nothing to do.
  region: "Asia"   population: 11937000   landlocked: false
  Each one becomes its own column.

  2. An object (a dict, inside { }): split into columns.
  area: {"kilometers": 89342, "miles": 34495.1}
  becomes the columns area.kilometers and area.miles. The same applies to
  names.common, codes.alpha_3 and coordinates.lat. pandas does this
  automatically with pd.json_normalize().

  3. A list of simple values (inside [ ]): this is where the hard part starts.
  borders: ["IRQ", "ISR", "PSE", "SAU", "SYR"]
  Jordan has 5 borders, Russia has 14, and an island has 0. A list doesn't fit
  in one cell. The same goes for timezones, continents and calling_codes.

  4. A list of objects: the hardest kind.
  languages:  [{"name": "Arabic", "iso639_3": "ara", ...}]
  currencies: [{"code": "JOD", "name": "Jordanian dinar", "symbol": "ا.د"}]
  capitals:   [{"name": "Amman", "coordinates": {...}, "attributes": {"primary":
  true}}]
  Here we have to choose which piece to keep (for example the language name) and
  how to store several values.

  The main design decision (yours): how to store the lists

  Option: A. Joined text + count
  What it looks like: borders = "IRQ, ISR, PSE, SAU, SYR", border_count = 5
  Pros: One row per country, simple and easy to chart. The count is very useful
  (e.g. "countries with the most neighbours").
  Cons: The individual values are inside text, so filtering "all countries that
  speak Arabic" needs a text search.
  ────────────────────────────────────────
  Option: B. Explode (one row per value)
  What it looks like: Jordan appears 5 times, once per border.
  Pros: Each cell holds one value.
  Cons: ❌ Breaks the statistics. Jordan's population would be counted 5 times,
  so totals and averages become wrong.
  ────────────────────────────────────────
  Option: C. Main table + separate small tables
  What it looks like: A main table with one row per country, plus
  country_languages with one row per country-and-language pair, and so on.
  Pros: The cleanest database design.
  Cons: More files, more work, and more to explain. The syllabus asks for "a
  usable table" (singular).

  My recommendation is A. It meets the syllabus, keeps the statistics correct,
  and is the easiest to defend. Option C is more advanced, and you could mention
  it in your defense as an alternative you considered and why you didn't choose
  it.

  Other things we'll decide after that (not now)

  - Which columns to keep (the syllabus requires the important ones: name,

    capital), and which to drop (leaders, assets, _meta, demonyms and so on).
  - For lists of objects, which piece to keep, e.g. language name, currency code
    or name, and only the primary capital.
  - Where to save the flat table.

● What Gini is

  The Gini coefficient measures how unequally income is shared inside a country.
  In our data it's on a scale from 0 to 100:

  - 0 means perfect equality: everyone earns exactly the same.
  - 100 means total inequality: one person earns everything and everyone else
    earns nothing.
  - Real countries fall roughly between 24 and 60.

  Here's what our data shows:

  ┌─────────────┬──────────┬──────┬──────┐
  │             │ Country  │ Gini │ Year │
  ├─────────────┼──────────┼──────┼──────┤
  │ Most equal  │ Slovakia │ 23.8 │ 2023 │
  ├─────────────┼──────────┼──────┼──────┤
  │             │ Belarus  │ 24.4 │ 2020 │
  ├─────────────┼──────────┼──────┼──────┤
  │ Least equal │ Botswana │ 54.9 │ 2015 │
  ├─────────────┼──────────┼──────┼──────┤
  │             │ Namibia  │ 59.1 │ 2015 │
  └─────────────┴──────────┴──────┴──────┘

  For comparison, Jordan's latest value is 33.7 (2010).

  Things to know before you decide

  1. It's missing for 83 of the 254 records. Only 171 have a value. That's
     mostly small territories and countries without surveys.
  2. The years differ a lot. We'd take each country's latest value, but "latest"
     ranges from 1992 to 2025. That makes comparing Namibia in 2015 with
     Slovakia in 2023 a bit unfair. We'd also keep a gini_year column so this
     stays visible.
  3. The benefit: it opens up interesting chart questions, like "Is inequality
     higher in some regions?" or "Do bigger countries have higher inequality?".
     It's also a realistic missing-values case for profiling, much more
     interesting than a column with no gaps.

  By default, read_csv turns some "missing-looking" text into real missing
  values (NaN): empty cells, "NA", "N/A", "null" and others.

  ┌───────────────────────┬───────────┬────────────┬───────────────────────┐
  │                       │ Jordan JO │ Namibia NA │  Somaliland (empty)   │

  │ keep_default_na=False │ JO ✅     │ NA ✅      │ '' ❌, hidden missing │
  └───────────────────────┴───────────┴────────────┴───────────────────────┘

  - The default has a trap: Namibia's real ISO code is "NA", and pandas thinks
    it means "Not Available" and deletes it. That's a famous data-engineering
    bug, and it's in our data.
  - keep_default_na=False fixes Namibia, but brings back our old problem.
    Somaliland's empty code stays as '', and pandas reports 0 missing, which
    hides the problem we found in extraction.

  So neither setting alone is correct.

  3. The correct combination

  pd.read_csv(path, keep_default_na=False, na_values=[""])
  This means: don't use pandas' default list of missing-value words; only an 
  empty cell counts as missing. Then Namibia keeps "NA" and Somaliland's code is

  also add the Namibia trap to the flattening log, because it's a strong point

  1. Borders: exactly. An empty borders cell is true information ("this country
     has no land neighbours"), not lost data. If we dropped those rows, we would
     delete 86 real countries, including Japan, Australia and the UK, and every
     statistic and model after that would be biased. Filling them would be just
     as bad: it would invent neighbours that don't exist. In cleaning we'll
     keep them and rely on border_count = 0.

     population on every row, so totals and averages would be inflated.
     Countries with many neighbours would be inflated the most: China and Russia
     have 14 borders each, so they would be counted 14 times. Comparing the
     population total before and after flattening is exactly the check that
     catches that.

    masking. That's why it finds so few. It's a poor fit for skewed data.
  - Log IQR: after the log, the data is roughly balanced, so it finds the truly
